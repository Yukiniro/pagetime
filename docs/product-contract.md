# 产品与界面约束

Product name: PageTime. Preserve existing storage keys and record formats when changing branding. The selected brand mark is the page-and-clock symbol in `assets/branding/pagetime-logo.png`; generate packaged sizes with `npm run icons`.

Design feedback (2026-10-24): the current UI's typography is too large and its spacing is too tight. Future UI work should reduce oversized text and give content more breathing room, with font size and spacing designed together. The selected overview direction combines Linear's light navigation with Plausible's open analytics canvas: borderless KPIs, underlined chart tabs, two aligned ranking lists, and subtle relative row bars. Apply the same typography, spacing and light dividers to Visits, Settings and site detail sheets.

Website homepage decision (2026-10-25): selected the first displayed marketing concept, `exec-d6ce82a7-f468-4974-a543-7f6d60cffa47.png`: centered headline and download action, a large straight-on dashboard image, three light trust statements, and a browsing timeline below. Follow-up feedback: provide more substantive content, following OtterTap's product/features/privacy/install/FAQ reading path and using 21st as a component reference. Product images containing text must have Chinese and English editions: Chinese locales use Chinese imagery; other locales use English imagery while the page copy stays localized. The standalone website is `home.html`; preserve the empty dashboard preview at `/`. Homepage spacing feedback (2026-10-25): use generous section spacing and room between headings, copy, actions and images; keep capabilities in two spacious columns on desktop and one on mobile, with comfortable installation steps and FAQ rows. Avoid enlarging typography to create hierarchy. Marketing examples stay separate from the ledger. Installation documentation uses the Chrome Web Store as the primary entry and GitHub ZIP as a manual alternative.

The UI is localized with react-i18next in Simplified Chinese, Traditional Chinese, English, Japanese, Korean, German, Spanish, French, Brazilian Portuguese, and Russian. Never hardcode user-facing text: keep extension resources in `src/locales/` and independent website resources in `website/locales/`; add each surface's strings to all ten of its locale files (with all plural forms the language needs), format dates/times/durations through that surface's `i18n.js`, and keep manifest text in `public/_locales`. `npm test` enforces key, placeholder, and plural parity.

Use the official shadcn Base UI components for available primitives. Prefer DropdownMenu for dropdown choices; avoid Select and native select. Keep the WXT extension and local preview on the same component and theme foundation.

The user selected the light blue analytics design. Theme defaults to system (`prefers-color-scheme`), with light and dark overrides stored in the existing settings record. The overview is a one-page ledger. The top-bar range is today, the last 7 days, the last 30 days, or a custom closed local-day interval; the default is today. Last 7 and last 30 include today and split on local midnights. A custom range whose end day is before its start day cannot be applied: the previous range stays, and the panel explains why. Both custom date inputs use the local day recording began as their minimum. When that start is not a finite time, the minimum is the earliest local day stored in the ledger (day, hour, visit, or span rows; hostnames alone do not count), and an empty ledger uses today. A start or end before that day is not applied: the previous range stays. The KPI bar's largest figure is active time for the selected range, plus visit count and site count, with no productivity score; while the range is today those figures are today's. Each KPI carries a neutral change line against the previous period of equal length right before the range (no red/green, no better/worse wording); a range that includes today is compared up to the current whole hour on both sides, and a previous period that starts before the first recorded day, or whose visit rows have passed the 31-day retention, shows only a dash instead of a number or percent, and its tooltip is at most one sentence; the full rules are in `docs/timing.md`. One primary chart is visible at a time. A single local day, including today, opens on that day's timeline, and the other tab is the last 7 days ending on that day. A multi-day range opens on that range's daily trend, and the timeline tab remains today. Clicking a bar that has a value on that daily trend, including the 7-day trend tab of a single day, sets the range to that local day: today uses the today preset, and any other day is a one-day custom range, so the chart opens on that day's timeline. Each of those days is also a button on the same path, so a keyboard or switch can select it. An unrecorded empty bar does not change the range. The site filter and an open site detail stay. Under a site filter, a recorded day that has visits and no active time still shows that one-pixel bar; a site with no rows in the range keeps the empty filter state. The site-detail daily trend uses the same click and keeps that site's drawer open. On a single day, the site-detail HourChart can be clicked to filter the session list, including an hour with no active time; each of those hours is also a button on the same path, so a keyboard or switch can select it. That click does not change the range. Overview heatmap cells still cannot filter by hour. When the selected range covers more than one local day, site detail does not show the active-session list. A single local day still shows that day's sessions. Previous and next buttons sit beside the date control on the overview and the visit list; they shift the closed interval by its own length and then show it as a custom range. Next stays disabled when the range already ends on today, and previous stays disabled when another full step would start before the local day of the first recorded day. Arrow left and arrow right do the same shift, except while focus is in a field or a drawer, dialog, or menu is open. A single day past detail retention shows that day's 24 hour bars from the stored hour totals, with no extra explanation. A site filter key stays put and is recomputed for the new range. Site rankings sit in two columns with a light relative bar. The activity heatmap stays collapsed until it is opened, then uses the selected range. While a site filter is on it averages only that merged site, and a filtered site with no hour rows in the range shows the chart's clear-filter empty state. Clicking a heatmap cell does not filter by hour. Settings, the ignore list, and clear stay in settings. There is no site-merge control. The interface states no timing rules, storage model, or retention numbers, except the one-line Visits empty state for a range past detail retention (`records.expired`, which says visit details are kept for the last 31 days and day totals stay on the overview): there is no how-it-works dialog, no measurement section, no local data overview, and no privacy block in settings. Those rules live in `docs/timing.md` and `docs/timing.zh-CN.md`, and the only privacy text in the interface is the sidebar `localNote`. Settings ends with one line of links, "Timing rules and privacy notes" and "Privacy policy", that open the repository docs in a new tab; the extension itself makes no request. The two real switches, keep counting while audio plays and the idle threshold, sit under Browsing records. Export data also lives in settings: JSON is the whole ledger plus recording state and settings, CSV is one row per local date and raw hostname. The file is built in the page and saved through a Blob download link, with no `downloads` permission and no network. After a JSON or CSV export is saved, a short read-only summary sits with that status: export time, time zone, the first and last day-total dates when the ledger has any, site count, and day-total row count. JSON also says settings are included and shows the extension version. A failed export shows no summary. There is no local-data overview block. Restore from backup reads a local JSON file in the page, parses the JSON in a worker, and checks every row before the confirm opens. A file that fails shows only the error, never opens the confirm, and leaves the ledger unchanged. A file that passes opens the one confirm with a read-only backup summary: export time, format version, first and last day-total dates, site count, row counts for each table, whether settings are included, and the extension version when the file has one. Cancel discards the file; confirm overwrites the ledger and settings inside the extension only; the preview disables it and does not write preview storage. CSV is not accepted. The toolbar badge defaults to on and shows today's total active browsing time only; the current site's time for today is only in the toolbar hover title. Clicking the toolbar icon opens a 320px popup instead of the dashboard: the current site's active time today, today's total, up to five of today's top active sites (same grouping and order as the dashboard's today ranking, site icon, name, and time; a row opens that site's detail the same way as the site name below; nothing is rendered when today has no active time), a list toggle for this hostname (blacklist `ignored` or whitelist `allowed`, no confirmation, click again undoes), pause or resume, and the badge switch. When that site has active time today, its name is a button (accessible name like “View <site> in the dashboard”) that opens or focuses the dashboard on today and opens that site's detail drawer. The address is `dashboard.html#site=` and the hash is removed as soon as it is read, so a refresh does not open the drawer again. Matching an open dashboard ignores its query and hash: no second tab and no full reload. A dashboard that is on Settings or a dialog returns to the overview before the drawer opens. The jump clears any site filter already on the overview and does not set one, so closing the drawer leaves today unfiltered. The site uses the same grouping as the popup. Open dashboard still only focuses an existing dashboard tab. A page without an http(s) hostname, or a site with no active time today, keeps the name as text. The popup stores no URL and adds no permission. When the popup has a current site, the same SiteIcon used on the dashboard sits in a fixed 24px slot beside the name. The favicon cache uses the raw tab hostname, and the packaged SVG uses the grouped site, then the globe. The name ellipsizes and the row stays inside the 320px popup. A page without a site shows today's total and no icon. Range selection is not stored.

Site grouping strips a leading `www.` / `m.` / `mobile.` before the overview, ranking, trend, and detail group a hostname. Visit history still shows the raw hostname. Grouping is a query view: Dexie keeps the raw hostname, and stored rows are not rewritten. There is no setting for another grouping. The preview starts empty: do not seed sample browsing records, and do not add demo-mode labels or a control that restores sample data. `npm run build` builds WXT; `npm run build:preview` builds the Sites-ready preview. Keep the starter's preview runtime intact.
